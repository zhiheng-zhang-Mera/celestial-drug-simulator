# DEV-09 desktop HTML anatomy (v2 — real BodyParts3D surfaces)

The anatomy stage is a native embedded WebEngine child of the existing Tk panel, started by the
unchanged `python -m src.app` entry. The page renders the real BodyParts3D body surface and the bundled
organ / muscle meshes instead of the previous cylinder-and-sphere schematic. Windows Python with Tk and
the installed PySide6/QtWebEngine 6.12 is still required; no runtime package, CDN or network access is
added. Missing runtime, load failure or WebGL failure stays visible and the `简化视图` button keeps the
prior offline Tk renderer.

## Scene

- **Body surface:** FMA7163 skin from the pinned BodyParts3D mirror, re-derived at a fixed 12 mm
  deterministic grid (32,451 vertices / 87,302 triangles) because the organ bundle's 12k-face shell
  contained metre-long bridging triangles. Warm translucent tint (slider 5–35%, default 30%), a
  per-fragment geometric-normal rim, quiet studio lights and a real silhouette. No capsule/sphere
  body.
- **Organs:** real `brain`, `heart`, `lungs`, `liver`, `stomach`, `kidneys`, `bladder`, `testes` meshes
  with muted tissue colours, default 82% opacity. Selection gets a mint outline/emissive; source
  evidence associations use the existing `mechanism / metabolism / excretion / label_concern` colours.
  Structural membership (`members`) is navigation only, not evidence.
- **Muscles:** real `biceps`, `triceps`, `quadriceps` meshes, translucent, in the 肌肉群 layer, clickable.
- **Reproductive layer:** real `testes`; the uterus entry is a clearly labelled procedural
  schematic (`示意层`) because the source bundle has no uterus mesh.
- **Skeleton:** the source bundle contains no bones. There is no bone switch or fake bone mesh; the
  panel legend states `子宫示意 · 无骨骼层`.
- Ink stage `#0C0D0F`, no neon, no particles, no decorative animation. Stage overlay: vertical front /
  back / reset / auto-rotate / system-colour bar on the right edge (clear of the body), zoom/status,
  hover tooltip, loading progress and readable error state.

`assets/web/data/bodyparts3d.json` is a byte copy of the canonical organ bundle;
`assets/web/data/bodyparts3d.mjs` is generated by `tools/build_web_anatomy.py --skin-stl <FMA7163.stl>`
(see `assets/web/ATTRIBUTION.md` for provenance, hashes and the CC BY-SA 2.1 JP terms). The page imports
this local module; it never fetches.

## Protocol (unchanged)

Python owns identities and evidence. HTML receives only the region catalog, selected identity-derived
evidence, effect categories, members and the display substance name; no physiology, genotype or regimen
export is sent to the renderer. Selection returns a whitelisted region id via
Qt WebChannel → JSON-line stdout → Tk event queue.

The page still:
- calls `anatomy.ready()` after QWebChannel opens;
- exposes `window.applyAnatomyState(state)` and updates selection, evidence highlight, region label and
  the region list from it;
- calls `anatomy.selectRegion(region)` on a mesh click, with a catalog region id.

`interaction.mjs` keeps the tested `isVisible / isClick / visualStyle / trackMovement` exports and
semantics.

## Controls and state

- Left panel (200 px): selected region, one-line legend (evidence colour / uterus schematic / no bone
  layer), skin/organ/evidence-opacity sliders, compact two-column layer switches with a min-width/ellipsis
  cell guard, and an inline reproductive-layer select.
- Responsive panel rhythm: a compact spacing set is used when the WebEngine viewport is under 600 px tall
  (1200×800 and 1024×720 windows) so every control fits without a horizontal clip; a slightly looser
  rhythm is restored on tall stages (1440×900). `scrollbar-gutter: stable` reserves the scrollbar column
  so overlay scrollbars can never cover the second layer column.
- Stage toolbar: vertical front / back / reset / auto-rotate / system-colour buttons on the right edge,
  outside the body silhouette at 1024 / 1200 / 1440. System-colour toggles the existing evidence-neutral
  mode.
- Keyboard: `F` front, `B` back, `R` reset, `Space` auto-rotate.
- Initial camera is a front full-body framing from the real bounds (fit margin 1.025); orbit, wheel zoom
  and right-drag pan are available. Selecting a posterior muscle (triceps) reveals the back view;
  selecting biceps or
  quadriceps returns to the front. A request from the Python region directory also reveals the owning
  layer.

## Offline and security

All resources are local files under `assets/web` (`file:`); CSP remains
`default-src 'self' qrc: data:` / `connect-src 'none'`; Three.js comes from the existing `vendor/`.
Qt's request interceptor still allows only `assets/web` files, the WebChannel qrc script and data URLs.
Drug text is rendered with `textContent`. External links remain Python's explicit browser action.

## Validation

Run from the repository root: `python -m unittest discover -s tests` (85 passed) and
`node --test tests/web_anatomy.test.mjs` (4 passed). Native validation used the same
`CELESTIAL_DRUG_TITLE='Celestial Drug (anatomy)'` override and the existing capture tooling. The page
logged first-frame times of ~0.7–0.9 s at 1440×900; `data/cache/webview.log` contained no Traceback and
no JavaScript error. Screenshots at 1440 / 1200 / 1024, front / back / liver-selected, are in
`_evidence/ui-modernization/final/medical/drug-body-v2-*.png`; the full report is
`_evidence/ui-modernization/modules/medical-anatomy-v2.md`.

The page text and data are not a clinical claim. The body is one adult male reference; uterus is a
schematic; the shell/organ LODs are display simplifications. The Tk footer geometry note (`几何：用户指定
HTML 原稿 / 补充示意…`) is owned by `src/body_ui.py`, which is outside this change; the authoritative
provenance is in the HTML panel and `assets/web/ATTRIBUTION.md`.
